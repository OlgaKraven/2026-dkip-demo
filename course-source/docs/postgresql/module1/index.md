# Модуль 1. Проектирование ER - диаграммы

## 1. Цель работы
На основании документов, представленных заказчиком, необходимо спроектировать **ER-диаграмму** для информационной системы предприятия.

## 2. Описание предметной области
Предприятие:

- **производит продукцию** согласно установленным **спецификациям**;
- **реализует готовую продукцию заказчикам**;
- каждая продукция имеет **цену**, которая **зависит от стоимости материалов**.

## 3. Требования к ER-модели
При проектировании ER-диаграммы необходимо обеспечить:

1. **Третью нормальную форму (3НФ)**  

   - исключить дублирование данных;  
   - разделить сущности так, чтобы каждый неключевой атрибут зависел только от ключа и не имел транзитивных зависимостей.

2. **Ссылочную целостность**  

   - все связи должны быть реализованы через корректные **внешние ключи (FK)**;  
   - связи «родитель—дочерняя сущность» должны быть логически обоснованы.

3. **Согласованную и осмысленную схему именования**  

   - единый стиль наименований таблиц и атрибутов (например: `Product`, `Material`, `Customer`, `Specification`);  
   - единые правила для ключей: `id`, `product_id`, `material_id`, и т.д.

4. **Ключи**

   - создать необходимые **первичные ключи (PK)** для каждой таблицы;  
   - создать необходимые **внешние ключи (FK)** для связей между таблицами.

> Типами данных на данном этапе можно пренебречь (достаточно перечислить атрибуты и ключи).

## 4. Формат результата
ER-диаграмма должна быть оформлена и представлена:

- **в формате `.pdf`**
- должна содержать:

  - таблицы (сущности),
  - атрибуты (поля),
  - первичные и внешние ключи,
  - связи между таблицами (1:1, 1:M, M:N — при необходимости).
